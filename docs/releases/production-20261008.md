发布采集时间关联、实际可导出质量报告及原生第一人称质量 HUD。

- [xr_teleoperate](https://github.com/lizuju/xr_teleoperate/tree/production-20261008)：遥操、连续采集、质检与训练导出。
- [VisionProTeleop](https://github.com/lizuju/VisionProTeleop/tree/production-20261008)：R1 Tracking Streamer 原生第一人称客户端。

## 变化

- 保存真实接受的手臂请求历史与对应成功发布，以已完成的手部请求为共同时间锚生成训练动作；保持姿态或开始新一条时禁止借用之前的历史。原始动作、命令、XR 与时间保留。
- 三路相机按实际时间跨度选择最新完整合格组合，保留 25 ms 门槛、缺帧和时钟失效信息，不插值或修改时间。
- 检查生成手指目标的真实输入年龄。导出保留选中的请求序号、动作锚点、左右输入时间与年龄，IMU 不进入训练输入。
- 质检与导出共用默认连续 40 帧门槛，显示最长片段、可导出段数/帧数和过短片段。自定义导出长度时，输出的质量报告使用实际门槛。
- 保存后后台质检结果按录像目录回传，原生原位置状态栏显示第几条、质检进度与实际导出可用性；“…”内查看详细原因。失败、丢弃和未标记数据不进入默认成功示范导出。

## 启动

更新 Ubuntu 代码及对应原生 App 后，在项目目录运行：

```bash
./teleop/run_r1_a7_visionpro_capture.sh 192.168.124.68 这次测试名 "这次测试目标"
```

`r` 跟随，`s` 开始一条，`y/n/x` 保存并标成功/失败/丢弃，下一条再按 `s`。Safari 使用现有网页入口。详见[质检与训练导出说明](../../outputs/数采质检与ACT训练导出.md)。
